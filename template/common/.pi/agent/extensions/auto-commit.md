# auto-commit — автоматический коммит после итерации агента

pi-расширение: после каждой **завершённой** итерации (вопрос пользователя →
финальный ответ агента, без продолжений pi) проверяет рабочую папку и делает
git-коммит накопившихся изменений. **По умолчанию выключено.**

## Точка срабатывания

Триггер — событие `agent_settled` (а не `agent_end`): оно означает, что прогон
закончен и pi больше ничего не продолжит сам (авто-ретрай, авто-компакт,
продолжение очереди уже исключены). Коммит выполняется в фоне и не блокирует
ввод.

## Алгоритм

1. Конфиг включён? → нет: ничего.
2. `git rev-parse` — рабочая папка репозиторий? Нет → уведомление один раз
   за сессию (если `notifyOnNonRepo`).
3. `git status --porcelain` — чисто? → ничего.
4. В репозитории идёт merge/rebase/cherry-pick? → пропуск (уведомление).
5. Сбор материалов: последний запрос пользователя + последний финальный
   ответ агента (из сессии) + `git diff HEAD` (+`--stat`) + porcelain-статус.
6. Тема коммита — **текущая модель сессии** (`streamSimple`, maxTokens=64):
   на вход запрос + ответ + обрезанный дифф; Conventional Commits, ≤72
   символов, язык — как у запроса. Ошибка/таймаут модели → fallback-тема
   `chore: auto-commit after "…"` (коммит всё равно выполняется).
7. `git add -A` (уважает `.gitignore`) + pathspec-исключения из `exclude`.
8. `git commit -F` — тело: тема, `User request:`, `Agent answer:`,
   `Changed files:` (запрос и ответ обрезаются до `maxMessageChars`).

Отказобезопасность: перед каждой мутирующей git-операцией проверяется
`ctx.isIdle()` — если пользователь уже отправил новый запрос, коммит молча
откладывается и изменения подхватит следующая итерация. Ошибки git —
`ctx.ui.notify` + строка в `~/.pi/agent/auto-commit.log`.

## Конфиг

Глобальный: `~/.pi/agent/auto-commit.json` (в pibox — файл **слоя user**,
`$PIBOX_DIR/template/user/.pi/agent/auto-commit.json`; применяется при
каждом запуске). Пер-проектный override: `<проект>/.pi/auto-commit.json`
(merge: глобальный → проектный).

```jsonc
{
  "enabled": false,          // выключено по умолчанию
  "maxDiffChars": 10000,     // обрезка диффа в промпте модели
  "maxMessageChars": 2000,   // обрезка запроса/ответа в коммите
  "exclude": [],             // pathspec для git add, напр. ["dist", "*.log"]
  "notifyOnNonRepo": true,   // уведомить, если папка — не git-репозиторий
  "titleTimeoutMs": 300000   // таймаут запроса темы к модели
}
```

`/autocommit [on|off|status]` — статус и переключение. Переключение пишет
глобальный конфиг в окружении: **живёт до перезапуска** — для постоянного
включения `pibox user pull .pi/agent/auto-commit.json` (промоут в слой user).

## Заметки

- Модель — текущая модель сессии: на медленных локальных серверах
  (LM Studio без кэша префикса) тема добавляет один полноценный запрос;
  таймаут регулируется `titleTimeoutMs` (при срыве — fallback-тема).
- Коммит создаётся от текущего git-identity; без настроенного
  `user.name`/`user.email` git откажется — ошибка придёт уведомлением.
- После прерывания итерации (Ctrl+C) коммит всё равно выполняется —
  на диске уже лежат реальные изменения.
