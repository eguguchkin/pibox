# terminal-probe — снимки экрана консольной программы для агента

Инструмент `terminal_probe` (pi-расширение) позволяет агенту **видеть**, как
консольная программа визуально рендерит свой вывод: прогресс-бары, перерисовки,
цвета, полноэкранные TUI.

## Зачем

При обычном запуске (`bash run.sh ...`) stdout — не TTY: программы отключают
прогресс-бары и цвета, и агент видит только финальный текст. Если же
перенаправить вывод в файл, агент получает сырые escape-последовательности,
из которых не видно, что реально было на экране пользователя.

`terminal-probe` запускает команду под **настоящим псевдо-терминалом**
(утилита `script`), эмулирует терминал (курсор, очистка, прокрутка,
альтернативный экран, SGR-цвета) и складывает на диск **текстовые снимки
экрана** — по файлу на кадр.

## Формат результата

```
<session>/meta.json              — команда, размер экрана, список кадров
<session>/frames/0001_0.01s.txt  — снимок: имя = номер кадра + таймкод
```

- Снимок — текстовый файл: шапка `#`-комментариями (время, хэш, курсор,
  alt-screen, скрытие курсора) + сетка символов экрана; цвет передан
  ANSI SGR-кодами прямо в тексте.
- Кадр, идентичный предыдущему (sha256), НЕ копируется — вместо полного
  снимка пишется маркер `# SAME AS PREVIOUS` с номером кадра-оригинала.

## Использование (инструмент агента `terminal_probe`)

| action | параметры | результат |
|--------|-----------|-----------|
| `run`  | `cmd` (shell-строка), опц. `cols` (100), `rows` (30), `outDir` | запуск + сводка: путь сессии, число кадров, список уникальных |
| `list` | `session` | список кадров: `+` уникальный / `=` дубль |
| `read` | `session`, `frame` | содержимое снимка кадра |

Типовой сценарий агента: `run` → просмотр списка → `read` нескольких ключевых
кадров → анализ (ассертов в туле нет — оценку визуальной корректности агент
делает сам).

## Использование как CLI

```bash
node --experimental-strip-types terminal-probe.ts run --cols 100 --rows 30 -- <команда...>
node --experimental-strip-types terminal-probe.ts list <session-dir>
```

CLI-режим удобен для отладки самого расширения; сессии по умолчанию
создаются в `/tmp/tprobe/run-<метка времени>/`.

## Ограничения

- Частота кадров ограничена granularity'й чанков `script -f` (обычно
  достаточно; паузы без вывода кадров не порождают — их отсутствие видно по
  разрыву таймкодов).
- Поддержаны типовые CSI-последовательности (CUU/CUD/CUF/CUB/CUP/ED/EL/SGR,
  `?1049`, `?25`); экзотика (scroll regions, вставка строк) игнорируется —
  для задач «проверить визуальный вывод» этого достаточно.
- Без нативных зависимостей: pty через системный `script`, эмулятор — чистый TS.
