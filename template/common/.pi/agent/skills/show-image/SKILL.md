# Показ картинок в pi-web-ui

В веб-интерфейсе (pi-web-ui) показать картинку пользователю можно только
markdown-изображением в тексте ответа. Тул-карточка `read` юзеру картинку
не показывает (только агенту), rawHtml выключен, у `.md img` нет max-width —
поэтому большие картинки дают горизонтальный скролл, а путь к файлу в `src`
надо указывать готовым URL.

## Как показывать

Просто выполни:

```bash
imgfit <оригинал> [макс-ширина=800]
```

и вставь его вывод в ответ **дословно** (обе строки): markdown-картинку и
подпись с данными оригинала.

`imgfit` (в `~/.local/bin`, требует venv `~/.pi/agent/venv-img` с Pillow):

- кладёт уменьшенную копию-превью в `/tmp/imgfit/` — вне workspace,
  артефактов в проекте нет; `/tmp` очищается при перезапуске контейнера;
- печатает готовый URL вида `![имя](/api/file?path=/tmp/imgfit/…-w800.jpg)`
  и подпись `*оригинал: \`путь\` · Ш×В · размер · превью …*`;
- если оригинал уже ≤ заданной ширины — использует его как есть.

## Почему именно так (механика pi-web-ui)

- `/api/file?path=<абсолютный путь>` — единственный эндпоинт, раздающий файлы
  **вне workspace** (у `/api/preview` containment-проверка hardcoded, настроек
  отключения нет). Без `clientId` работает для любых абсолютных путей.
- Оригиналы не трогаем и не копируем в workspace — они лежат там, где лежат
  (например `~/.pi/images` — дефолтный outputDir pi-image-gen).
- Превью ≤800px, т.к. вьюпорт узкий и у `.md img` нет max-width.
- В TUI ссылка деградирует в текст — это приемлемо (скилл только для web-ui).

## Кому-то это может пригодиться для отчёта апстриму

`/api/file` без containment для абсолютных путей = чтение произвольных файлов
для любого, у кого есть доступ к UI (в pibox смягчено localhost-биндингом и
PI_WEB_TOKEN для LAN). Плюс отсутствие `.md img { max-width: 100% }` в CSS.
