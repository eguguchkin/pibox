# AGENTS.md — глобальные инструкции для агента в pibox

Ты запущен внутри Docker-контейнера pibox: Ubuntu 24.04, архитектура как у
хоста (arm64/amd64). Ресурсы лимитированы (по умолчанию 4 ГБ RAM, 2 CPU,
512 pids).

## Где ты и что персистентно

- **Нет root и sudo**, `apt install` недоступен. Ты работаешь от `pi`
  (UID/GID = пользователь хоста): создаваемые файлы сразу принадлежат ему,
  chown не нужен.
- Персистентны только `$HOME` (/home/pi) и `/home/pi/workspace` — bind-mounts
  с хоста. Всё остальное (включая /usr, /etc) сбрасывается при перезапуске.
- `/home/pi/workspace/<проект>` (твой cwd) — данные пользователя на его
  машине: всё, что ты тут меняешь, меняется у него. Правила работы — скилл
  workspace-hygiene (загрузи перед массовыми правками и git-операциями).
- Часть конфигурации агента (`~/.pi/agent/`: models.json, USER.md, личные
  расширения и их конфиги) управляется **снаружи**: эти файлы перезаписываются
  из пользовательского слоя pibox при каждом запуске контейнера. Правки их
  внутри контейнера живут до следующего старта — не правь молча; скажи
  пользователю, что и куда добавить (он сохранит через `pibox user pull`).

## Предустановлено (в образе — не ставь повторно)

- CLI: curl, wget, git, jq, yq, ripgrep, rsync, ssh, tmux, lsof, file, vim,
  htop, ncdu.
- Сеть: dig, nslookup, ss, ping. Нет: nc, telnet, traceroute.
- python3 (pip заблокирован PEP 668 — только venv), node, make + g++
  (нативные npm-сборки node-gyp идут штатно), JRE headless,
  tesseract-OCR (eng+rus), shellcheck, shfmt.
- mise — тулчейны (go, rust, php, другие версии python/node…). Порядок
  установки языков — скилл install-languages (загрузи при первой установке).

## Сеть

- Серверы слушать на `0.0.0.0` (не 127.0.0.1) и на порты ≥1024:
  привилегированные порты (<1024) на части хостов закрыты (нет
  CAP_NET_BIND_SERVICE) — не полагайся на них.
- Хост-сервисы (локальная LLM API, БД) — `host.docker.internal:PORT`;
  `localhost` внутри контейнера — это сам контейнер, не хост.
- Хост видит контейнер только на портах, опубликованных `pibox -p` — этот
  флаг контролирует пользователь, попроси его перезапустить с нужным мапом.
- Диагностика соединений — скилл networking.
- Браузерный UI агента (pi-web-ui) вшит в образ и запускается пользователем
  с хоста (`pibox webui`, по умолчанию порт 8787); сессии и модели общие с
  TUI. Веб-интерфейс — единственное место, где тебе доступен показ картинок
  (скилл show-image).
- Telegram-мост (pi-telegram-bridge, `pibox tg`) вшит в образ: задания и
  отчёты через бота (@llblab/pi-telegram). Токен — в
  `~/.pi/agent/telegram.json` (user-слой). Если api.telegram.org закрыт
  провайдером, запросы к Telegram автоматом идут через SOCKS5-прокси —
  переменная PIBOX_TELEGRAM_PROXY (socks5h://user:pass@host:port),
  управляет пользователь. Твои ответы в этот чат стримятся мостом сам;
  файлы для отправки — инструмент telegram_attach.

## Git

- `~/.gitconfig` по умолчанию нет → первый коммит упадёт («Please tell me
  who you are»). Спроси имя/email у пользователя, настрой `git config
  --global` (персистентно в окружении) или `--local` в проекте.
- «detected dubious ownership» не чинить chown'ом — пользователю флаг
  запуска `pibox --git-safe`.
- Секреты (API-ключи, models.json с ключами) не коммитить и не выводить в лог.

## Известные особенности

- npm prefix уже настроен entrypoint'ом на `~/.local` (персистентно) — не меняй.
- Сеть открыта (если хост не ограничил): curl/wget/git работают.
- Долгие команды (сборки, загрузки тулчейнов ~100–200 МБ) — норма,
  не обрывай раньше времени.
- TTY может отсутствовать — используй неинтерактивные флаги (-y, CI=1).
- `/tmp` не персистентен — годится для scratch в рамках сессии, не для важного.
- Capabilities сброшены: трассировка чужих процессов и сниффинг трафика
  недоступны (strace/tcpdump в образ не входят).
- Шим-пакеты SDK (`@earendil-works/pi-coding-agent`, `pi-tui`, `pi-ai` в
  `~/.pi/agent/npm/node_modules/@earendil-works/`) — реэкспорт настоящего SDK
  из `/usr/local/lib/node_modules` (раннеры субагентов резолвят его от
  npm-дерева окружения). Восстанавливаются entrypoint'ом при каждом старте
  контейнера; если npm их вычистил посреди сессии (после `pi install`),
  перезапусти контейнер — или скажи пользователю.

## Конфигурация агента

- Сессии: `~/.pi/agent/sessions/` — персистентны.
- Модели: `~/.pi/agent/models.json` — из пользовательского слоя (см. выше).
- Личные инструкции пользователя: `~/.pi/agent/USER.md` — если существует,
  учитывать в работе наравне с этим файлом.
- Скиллы: `~/.pi/agent/skills/` — персистентны.
- Этот файл — глобальный AGENTS.md окружения; его источник — шаблон pibox
  (template/common), обновляется при пересоздании окружения.
