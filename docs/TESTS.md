# TESTS.md — как тестировать pibox

## Вне контейнера (на хосте, есть docker-демон)

```bash
./tests/smoke.sh                 # полный прогон: фазы 0-4 (~2 мин, первый — дольше из-за сборки образа)
./tests/smoke.sh --rebuild       # пересобрать образ pibox:latest
./tests/smoke.sh --offline       # без проверки интернета (R14)
./tests/smoke.sh --keep          # сохранить временный каталог при успехе
```

## Внутри контейнера pibox (docker-демона нет)

Внутри контейнера нет docker, но большая часть проверок к нему не
обращается — работают с файлами и CLI. Для них есть режим `--no-docker`:

```bash
./tests/smoke.sh --no-docker     # ~136 проверок, ~20 с; docker-фазы — SKIP
```

Что происходит: в начало `PATH` подставляется заглушка
`tests/docker-stub/docker` — минимальная эмуляция интерфейса docker ровно в
том объёме, который нужен не-docker фазам (`info`, `version`,
`image inspect`, `container inspect`, молчаливый `rm`). `build`/`run` заглушка
честно отклоняет — она их не имитирует.

Что покрывает `--no-docker`:

| Фаза | Содержимое | Режим |
|------|-----------|-------|
| 0 (P0) | требования: bash, версии | PASS |
| 1 (I1–I6) | install.sh: установка, структура, повторная, --force, слои | PASS |
| 2 (B0–B6) | docker build + содержимое образа | SKIP |
| 3 (C1–C27) | CLI dry-run, env, user push/pull, doctor D1-D9, манифест расширений, изоляция | PASS |
| 4 (R1–R20) | runtime контейнера: UID/GID, skel-merge, .npmrc, сеть, caps, лимиты, порты, webui | SKIP |

Причины, по которым фазы 2 и 4 принципиально не эмулируются: они проверяют
контракты настоящего демона (изоляция, capabilities, bind-mounts, сеть) —
подмена заглушкой превратила бы PASS в ложь. Правила:

+ Заглушке разрешено эмулировать только «есть ли образ/демон» и версии —
  ответы, от которых зависит *пропуск* docker-зависимых проверок, а не их результат.
+ Новая проверка, которой нужен живой демон, обязана стоять в фазе 2 или 4
  (между `if [ "$NO_DOCKER" = "1" ]`-страховками) и не использовать docker
  в фазах 0/1/3.
+ Прогон CI/хостом (`./tests/smoke.sh` без флага) обязан покрывать всё.

## Линт и стиль (работают везде, включая контейнер)

```bash
shellcheck install.sh entrypoint.sh webui.sh bin/pibox lib/*.sh tests/*.sh tests/docker-stub/docker
shfmt -d -i 4 install.sh entrypoint.sh webui.sh bin/pibox lib/*.sh tests/*.sh tests/docker-stub/docker
```

## Частые проблемы

+ `smoke: error: не найдена утилита: docker` без `--no-docker` — вы внутри
  контейнера; это ожидаемо, используйте `--no-docker`.
+ `--no-docker` с FAIL в фазах 0/1/3 — реальная регрессия CLI/установщика,
  а не окружение: чинить, не скипать.
+ Заглушка меняет `PATH` только внутри своего процесса (export в smoke.sh):
  последующие команды того же шелла настоящий docker не видят.
