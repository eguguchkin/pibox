# Слои шаблона окружений (design doc)

Статус: реализовано (кроме отмеченного). Автор решения — обсуждение
2026-09-20, см. историю коммитов.

## Проблема

1. Личные вещи владельца (Selectel-ключи, `selectel-thinking-off.ts`,
   конфиг pi-image-gen) лежали в коммитируемом слое продукта, а реальные
   ключи — только внутри env: пересоздание окружения теряло их.
2. `env/` совмещал шаблон и рантайм; обновление продукта не трогало
   персональные инварианты просто потому, что их негде было хранить.

## Решение

```text
$PIBOX_DIR/
├── template/
│   ├── common/   СЛОЙ 1: продукт, начальное состояние env
│   ├── user/     СЛОЙ 2: личные инварианты владельца
│   ├── extensions.txt
│   └── README.md
└── env/<name>/   рантайм (bind → /home/pi)
```

| | `template/common` | `template/user` |
| --- | --- | --- |
| Смысл | продукт: начальное состояние env | личные инварианты |
| Применяется | один раз, `env create` (`create_env`) | каждый запуск (`apply_user_layer`, lib/layers.sh) |
| `install.sh` | перезаписывает всегда | аддитивно (`additive_copy`), правки не трогает |
| В репо | реальные файлы | заглушки (`REPLACE_ME`, `$SELECTEL_API_KEY`); значения — в установке |

Правила:

- Слой 2 копирует только пути, существующие в `template/user`: ничего
  не удаляет, отсутствующие файлы в env не трогает (env — не производная:
  сессии/память/доустановленные расширения живут своей жизнью).
- Файл из `user` с тем же путём перекрывает `common` (лог предупреждает).
- `AGENTS.md` не склеивается: продуктовый в `common` ссылается на
  опциональный `USER.md` из `user`.
- Памяти в слоях нет — `memory/` живёт только в env.
- Opt-out: `PIBOX_NO_USER_LAYER=1`.
- Deny-list не вводился сознательно: множество путей слоя 2 задаётся
  самим содержимым `template/user`.

## Синхронизация

- Прямая (host → env): автоматическая — `apply_user_layer` в `create_env`
  и `launch_container`; вручную: `pibox user push`.
- Обратная (env → host): `pibox user pull [PATH…] [-n]` — без аргументов
  забирает все файлы слоя с дрейфом; с путём — промоутит в слой даже
  новый файл; `-n` показывает diff без записи. После выхода контейнера
  CLI печатает хинт о дрейфе.

## Манифест расширений

Один, продуктовый: `template/extensions.txt` (переписывается install.sh).
Личных манифестов нет — расширения, поставленные `pi install`, живут в env
и при пересоздании не восстанавливаются (осознанный пробел; при боли —
добавить `template/user/extensions.txt` в `pibox extensions install`).

## Сценарии

| Сценарий | Ход |
| --- | --- |
| Чистая установка | clone → install.sh → build → правка `template/user/.pi/agent/models.json` → `pibox user push` |
| Вторая машина | + перенос `$PIBOX_DIR/template/user/` (rsync / приватный репо) |
| Пересоздание env | `env remove` + запуск: слои применяются автоматически |
| Обновление | `git pull && install.sh`: common/манифест — всегда, user — аддитивно |
| Агент поправил конфиг | `pibox user pull [PATH]` |

## Отложено

- `pibox env backup` (сессии/память) — вне скоупа слоёв.
- Личный манифест расширений (см. выше).
- При `PIBOX_DIR` = клон репо (dev-режим) правки `template/user` видны в
  `git status` — секреты держать в отдельной установке.
