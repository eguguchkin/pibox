**PIBOX** — это инструмент для изолированного, безопасного и удобного запуска [Pi Coding Agent](https://pi.dev/) в Docker-контейнере.

## 🚀 Быстрый старт

### Требования
- Установленный и запущен **Docker**.
- Bash-совместимая оболочка (bash, zsh).

### 1. Установка
Склонируйте репозиторий и запустите установщик:
```bash
git clone https://github.com/your-repo/pibox.git
cd pibox
./install.sh
```
Установщик создаст директорию `~/pibox` (или `$PIBOX_DIR`), скопирует шаблоны и добавит CLI в ваш `PATH`. 
*Не забудьте перезапустить терминал или выполнить `source ~/.bashrc` (или `~/.zshrc`) после установки.*

### 2. Запуск агента
Перейдите в директорию вашего проекта и запустите `pibox`:
```bash
cd ~/my-awesome-project
pibox
```
Текущая директория автоматически примонтируется в `/home/pi/workspace` внутри контейнера, и Pi-агент начнет работу.

### 3. Использование специфичных окружений
Если вам нужен специфический стек (например, PHP 8 или Rust), используйте флаг `--env`. Окружение создастся автоматически из шаблона при первом запуске:
```bash
pibox --env php8
```

### 4. Проброс портов
Для запуска локальных dev-серверов внутри контейнера пробрасывайте порты флагом `-p`:
```bash
pibox -p 8080:8080
```

## 🏗 Архитектура

### Система окружений (`env`)
Вместо того чтобы пересоздавать контейнер и скачивать гигабайты зависимостей при каждом запуске, PIBOX использует систему персистентных окружений:
- Директория `~/pibox/env/<name>` монтируется как `/home/pi` внутри контейнера.
- Всё, что агент устанавливает локально (через `mise`, `npm`, `pip`), сохраняется в этой директории и переиспользуется.
- Новые окружения клонируются из `~/pibox/env-template/`.

### Механизм `/opt/skel` (Dotfiles)
При bind-монтировании `/home/pi` оригинальные системные конфиги контейнера (`.bashrc`, `.profile`) скрываются. Чтобы агент не остался без базовых настроек оболочки и инициализации `mise`, PIBOX сохраняет эталонный home в `/opt/skel` при сборке образа. При первом запуске `entrypoint.sh` аккуратно мерджит недостающие файлы из `/opt/skel` в ваше окружение, не затирая ваши кастомные настройки.

### Тяжелые тулчейны и `mise`
Базовый Docker-образ содержит только минимум (Python, Node.js, git, утилиты). Тяжелые компиляторы и отладчики (Rust, Go, CMake, GDB) **не включены в образ**. Агент устанавливает их "на лету" в `~/.local` с помощью версионера `mise`. Это keeps образ легким и позволяет гибко настраивать стек под конкретный проект.

## 🛡 Безопасность

### Защита Workspace
Запускающий скрипт (`bin/pibox`) строго проверяет рабочую директорию. Если вы случайно запустите `pibox` внутри самой директории `~/pibox` (или её подпапок), скрипт прервется с ошибкой. Это защищает конфигурации и шаблоны PIBOX от того, чтобы агент случайно отредактировал или удалил их.

### Capabilities и сеть
Контейнер запускается с минимально необходимыми, но достаточными для разработки правами:
- `--cap-add=SYS_PTRACE`: Позволяет использовать `strace`, `gdb` и другие отладчики.
- `--cap-add=NET_RAW`: Необходим для работы `tcpdump` и `ping`.
- `--add-host host.docker.internal:host-gateway`: Дает контейнеру доступ к сервисам, запущенным на хост-машине (например, к локальной LLM).

### Ограничения ресурсов
По умолчанию контейнер лимитирован (2 CPU, 4 GB RAM), чтобы runaway-процессы агента не могли повесить хост-машину.

## 🤖 Управление моделями и API

Конфигурация моделей хранится в файле `models.json`.
- **Глобальный шаблон:** `~/pibox/env/models.json`
- **В конкретном окружении:** `~/pibox/env/<name>/.pi/agent/models.json`

### Локальные модели
Для подключения к локальному API (например, Ollama или LM Studio на хосте), используйте адрес `http://host.docker.internal:8080`.

### Облачные API-ключи
**Не храните секретные ключи в `models.json`!** 
Вместо этого используйте переменные окружения. В `models.json` укажите `"api_key_env": "OPENAI_API_KEY"`, а сам ключ передавайте при запуске:

```bash
# Вариант 1: Экспорт в ~/.bashrc на хосте (pibox автоматически пробросит известные ключи, если настроить скрипт)
export OPENAI_API_KEY="sk-..."
pibox

# Вариант 2: Прямая передача (требует модификации bin/pibox или использования docker run)
```
*Рекомендуется прописать экспорт ключей в `~/pibox/env/<name>/.bashrc` — они автоматически подтянутся внутри контейнера.*

## 🛠 Troubleshooting

### Ошибка Git: "detected dubious ownership in repository"
При bind-монтировании Git может ругаться на смену владельца файлов. 
**Решение:** Запустите pibox с флагом `--git-safe`:
```bash
pibox --git-safe
```
Это автоматически добавит `/home/pi/workspace` в `git config --global safe.directory`.

### Файлы на хосте принадлежат `root` или `nobody`
PIBOX динамически подстраивает UID/GID внутри контейнера под вашего хост-пользователя. Если этого не произошло:
1. Убедитесь, что вы не запускаете `pibox` через `sudo`.
2. Проверьте, что переменные `HOST_UID` и `HOST_GID` корректно передаются (это делается автоматически в `bin/pibox`).

### `host.docker.internal` не резолвится (Linux)
На macOS и Windows Docker Desktop автоматически создает этот алиас. На Linux PIBOX добавляет его принудительно через `--add-host`. Если у вас все равно нет доступа к хосту, проверьте, не блокирует ли ваш локальный файрвол (ufw/iptables) подключения из docker-bridge сети.

### Агент не видит установленные через `mise` инструменты
Убедитесь, что в вашем окружении используется `.bashrc` из `env-template`, который содержит строку `eval "$(mise activate bash)"`. Если вы перезаписали `.bashrc` своим, добавьте эту строку вручную.
