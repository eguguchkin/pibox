Ниже представлена полная реализация **Задачи 3**. 

Скрипт `entrypoint.sh` — это сердце инициализации контейнера. Он выполняется от `root`, подстраивает права доступа под вашу хост-систему, аккуратно восстанавливает системные конфигурационные файлы (dotfiles) из эталона и безопасно передает управление агенту от имени непривилегированного пользователя.

### 📂 1. Структура файлов для этого этапа
В корне репозитория должен находиться:
```text
pibox-repo/
└── entrypoint.sh      # Скрипт инициализации (реализация ниже)
```

### 💻 2. Листинг файла

#### `entrypoint.sh`
Создайте файл со следующим содержимым и обязательно сделайте его исполняемым (`chmod +x entrypoint.sh`).

```bash
#!/usr/bin/env bash
set -euo pipefail

# ==========================================================
# PIBOX Entrypoint
# Отвечает за подготовку окружения внутри контейнера перед
# запуском агента. Работает от root, затем сбрасывает права.
# ==========================================================

# Читаем параметры хостовой системы, переданные через -e в docker run
HOST_UID=${HOST_UID:-1000}
HOST_GID=${HOST_GID:-1000}
PIBOX_GIT_SAFE=${PIBOX_GIT_SAFE:-0}

echo "=================================================="
echo " PIBOX Entrypoint"
echo "=================================================="

# ----------------------------------------------------------
# 1. Динамическая подстройка UID/GID пользователя 'pi'
# ----------------------------------------------------------
CURRENT_UID=$(id -u pi)
CURRENT_GID=$(getent group pi | cut -d: -f3)

if [ "$CURRENT_UID" != "$HOST_UID" ]; then
    echo "[1/4] Updating pi UID from $CURRENT_UID to $HOST_UID..."
    usermod -u "$HOST_UID" pi
else
    echo "[1/4] pi UID is already set to $HOST_UID."
fi

if [ "$CURRENT_GID" != "$HOST_GID" ]; then
    echo "[1/4] Updating pi GID from $CURRENT_GID to $HOST_GID..."
    groupmod -g "$HOST_GID" pi
else
    echo "[1/4] pi GID is already set to $HOST_GID."
fi

# ----------------------------------------------------------
# 2. Мердж эталонных dotfiles из /opt/skel
# ----------------------------------------------------------
# Флаг инициализации. Храним его в скрытой директории агента,
# чтобы не мусорить в корне окружения.
SKEL_FLAG="/home/pi/.pi/.skel_merged"

if [ ! -f "$SKEL_FLAG" ]; then
    echo "[2/4] First run detected. Merging /opt/skel into /home/pi..."
    
    # Создаем базовую структуру, если ее нет
    mkdir -p /home/pi/.pi
    
    # Копируем файлы. 
    # -r: рекурсивно
    # -n: не перезаписывать существующие файлы (защита пользовательских конфигов)
    # /. : копируем содержимое директории, а не саму директорию
    cp -rn /opt/skel/. /home/pi/
    
    # Создаем файл-флаг
    touch "$SKEL_FLAG"
    
    # Устанавливаем правильного владельца на служебные файлы
    chown -R pi:pi /home/pi/.pi
    
    echo "[2/4] Skel merge completed."
else
    echo "[2/4] Skel already merged. Skipping."
fi

# ----------------------------------------------------------
# 3. Исправление прав на директории агента
# ----------------------------------------------------------
# Если UID/GID менялись между запусками, файлы сессий в .pi/agent
# могли остаться с предыдущим владельцем. Исправляем это.
if [ -d "/home/pi/.pi" ]; then
    echo "[3/4] Fixing ownership of /home/pi/.pi..."
    chown -R pi:pi /home/pi/.pi
fi

# ----------------------------------------------------------
# 4. Настройка Git (Safe Directory)
# ----------------------------------------------------------
if [ "$PIBOX_GIT_SAFE" = "1" ]; then
    echo "[4/4] Configuring git safe.directory for workspace..."
    # Выполняем команду от имени пользователя pi
    gosu pi git config --global --add safe.directory /home/pi/workspace || true
else
    echo "[4/4] Git safe.directory configuration skipped."
fi

echo "=================================================="
echo " Initialization complete. Starting Pi Agent..."
echo "=================================================="

# ----------------------------------------------------------
# 5. Передача управления агенту
# ----------------------------------------------------------
# Используем gosu для сброса прав до пользователя 'pi'
# и tini для корректной обработки сигналов (SIGTERM/SIGINT).
exec gosu pi:pi tini -- pi "$@"
```

### 🧠 3. Пояснения к ключевым архитектурным решениям

1. **Зачем нужен `usermod` и `groupmod`?**
   Docker-контейнер по умолчанию использует жестко заданный `UID=1000` для пользователя `pi`. Но на вашей хост-машине пользователь может иметь `UID=501` (macOS) или `UID=1001`. Если мы не подстроим UID внутри контейнера, агент будет создавать файлы в примонтированном `workspace`, которые на хосте будут отображаться как принадлежащие пользователю `nobody` или `1000`, что создаст проблемы с правами. `entrypoint.sh` решает это "на лету".
2. **Почему `cp -rn /opt/skel/. /home/pi/`?**
   * Флаг `-n` (no-clobber) гарантирует, что мы **не затрем** пользовательские конфиги (например, кастомный `.bashrc`), если они уже есть в примонтированном окружении `env/<name>`.
   * Конструкция `/.` в конце копирует именно **содержимое** папки `/opt/skel`, а не саму папку, чтобы избежать вложенности вида `/home/pi/skel/`.
3. **Безопасность `chown`:**
   Мы делаем `chown -R pi:pi` только для директории `/home/pi/.pi` (конфиги и сессии агента). Мы **не** делаем рекурсивный `chown` на весь `/home/pi` или `workspace`, чтобы случайно не сменить владельца файлов вашего проекта на хосте. Так как мы уже подстроили `UID` пользователя `pi` под `UID` хоста, доступ к файлам проекта будет работать корректно без смены владельца.

### 🧪 4. Инструкция по тестированию

Так как `entrypoint.sh` копируется внутрь образа на этапе сборки, вам нужно пересобрать образ из **Задачи 2**, чтобы применить изменения.

1. **Сделайте скрипт исполняемым:**
   ```bash
   chmod +x entrypoint.sh
   ```

2. **Пересоберите Docker-образ:**
   ```bash
   docker build -t pibox-base:latest .
   ```

3. **Тест 1: Проверка подстройки UID/GID**
   Запустите контейнер с нестандартным `UID` и проверьте, что пользователь внутри контейнера получил эти права:
   ```bash
   docker run --rm -e HOST_UID=1234 -e HOST_GID=1234 pibox-base:latest id
   ```
   *Ожидаемый вывод: `uid=1234(pi) gid=1234(pi) groups=1234(pi)`*

4. **Тест 2: Проверка мерджа /opt/skel (Первый запуск)**
   Создайте временную директорию, которая сымитирует новое окружение:
   ```bash
   mkdir -p /tmp/pibox-test-env
   
   docker run --rm \
     -v /tmp/pibox-test-env:/home/pi \
     -e HOST_UID=$(id -u) \
     -e HOST_GID=$(id -g) \
     pibox-base:latest echo "Test completed"
   ```
   Проверьте содержимое директории:
   ```bash
   ls -la /tmp/pibox-test-env
   ```
   *Ожидаемый результат: В директории появились `.bashrc`, `.profile` (из эталона) и скрытый файл `.pi/.skel_merged`.*

5. **Тест 3: Проверка идемпотентности (Повторный запуск)**
   Запустите ту же команду еще раз. В логах контейнера вы должны увидеть:
   `[2/4] Skel already merged. Skipping.`
   Это подтверждает, что скрипт не копирует файлы повторно и не затирает пользовательские данные.
