Ниже представлена полная реализация **Задачи 5**. 

Шаблоны окружений (`env-template`) и конфигурация моделей (`models.json`) — это фундамент для создания изолированных рабочих пространств. Правильно настроенный шаблон позволяет агенту сразу иметь доступ к нужным директориям, истории, алиасам и менеджеру версий `mise`, а `models.json` обеспечивает гибкое подключение к различным AI-провайдерам.

### 📂 1. Структура файлов для этого этапа
В корне репозитория необходимо создать следующую структуру:

```text
pibox-repo/
├── env/
│   └── models.json              # Глобальный шаблон конфигурации моделей
└── env-template/                # Шаблон базового окружения для /home/pi
    ├── .bashrc                  # Настройка окружения, алиасы и инициализация mise
    ├── .local/                  # Директория для локально установленных тулчейнов
    │   └── bin/
    │       └── .gitkeep         # Файл для сохранения пустой директории
    └── .pi/                     # Конфигурации и данные агента
        └── agent/
            ├── extensions/      # Пользовательские расширения агента
            │   └── .gitkeep
            ├── skills/          # Пользовательские скиллы и промпты
            │   └── .gitkeep
            └── sessions/        # Деревья сессий (.jsonl)
                └── .gitkeep
```

### 💻 2. Листинги файлов

#### `env/models.json`
Этот файл будет скопирован установщиком (`install.sh`) в `~/pibox/env/models.json`, а затем скрипт запуска (`bin/pibox`) будет переносить его в каждое новое окружение при первом старте.

```json
{
  "default_model": "local-api",
  "models": {
    "local-api": {
      "provider": "openai-compatible",
      "description": "Local Model API running on the host machine",
      "base_url": "http://host.docker.internal:8080/v1",
      "api_key": "YOUR_LOCAL_API_KEY_HERE",
      "model": "default-model-name"
    },
    "anthropic-claude": {
      "provider": "anthropic",
      "description": "Anthropic Claude via API",
      "api_key_env": "ANTHROPIC_API_KEY",
      "model": "claude-3-5-sonnet-20241022"
    },
    "openai-gpt": {
      "provider": "openai",
      "description": "OpenAI GPT via API",
      "api_key_env": "OPENAI_API_KEY",
      "model": "gpt-4o"
    }
  }
}
```

#### `env-template/.bashrc`
Базовый конфигурационный файл оболочки, который будет попадать в каждое новое окружение. Он настраивает историю, алиасы и, что самое важное, активирует `mise` для локальной установки тулчейнов агентом.

```bash
# ==========================================================
# PIBOX Environment Template
# Этот файл копируется в новое окружение при первом запуске.
# ==========================================================

# --- Настройка истории ---
export HISTCONTROL=ignoreboth:erasedups
export HISTSIZE=10000
export HISTFILESIZE=20000
shopt -s histappend

# --- Алиасы для удобства ---
alias ll='ls -alF'
alias la='ls -A'
alias l='ls -CF'
alias grep='grep --color=auto'

# --- Настройка путей ---
# Добавляем локальные бинарники пользователя в PATH
export PATH="$HOME/.local/bin:$PATH"

# --- Инициализация mise ---
# Позволяет агенту устанавливать и использовать локальные версии
# языков и тулчейнов (rust, go, php, cmake и т.д.) без засорения образа.
if command -v mise &> /dev/null; then
    eval "$(mise activate bash)"
fi

# --- Переменные окружения для агента ---
# Раскомментируйте и заполните при необходимости:
# export OPENAI_API_KEY="sk-..."
# export ANTHROPIC_API_KEY="sk-ant-..."
```

#### `env-template/.gitkeep` файлы
Создайте пустые файлы `.gitkeep` в следующих директориях, чтобы они сохранились при копировании и архивации:
- `env-template/.local/bin/.gitkeep`
- `env-template/.pi/agent/extensions/.gitkeep`
- `env-template/.pi/agent/skills/.gitkeep`
- `env-template/.pi/agent/sessions/.gitkeep`

### 🧠 3. Пояснения к ключевым архитектурным решениям

1. **Зачем нужен `env-template/.bashrc`?**
   Поскольку `/home/pi` внутри контейнера полностью подменяется bind-mount'ом, стандартные системные конфиги становятся недоступны. Шаблонный `.bashrc` гарантирует, что в любом новом окружении (например, `php8` или `rust`) агент сразу получит настроенную историю, алиасы и, самое главное, активированный `mise`. Без инициализации `mise` в `.bashrc` агент не сможет использовать локально установленные тулчейны.
2. **Безопасность API-ключей в `models.json`:**
   В шаблоне `models.json` мы используем два подхода:
   * `api_key`: Прямое указание ключа (подходит для локальных моделей, где ключ не критичен).
   * `api_key_env`: Ссылка на переменную окружения (например, `ANTHROPIC_API_KEY`). Это рекомендуемый способ для облачных провайдеров. Ключи не хранятся в файле, а передаются в контейнер при запуске через флаги `-e` в `bin/pibox` или через `~/.bashrc` на хосте.
3. **Структура `.pi/agent/`:**
   Предварительно созданные директории (`extensions`, `skills`, `sessions`) избавляют агента от необходимости проверять их существование при первом запуске и гарантируют корректное сохранение деревьев сессий.

### 🧪 4. Инструкция по тестированию

1. **Обновите установленную систему:**
   После создания файлов в репозитории, выполните установщик, чтобы скопировать новые шаблоны в `~/pibox`:
   ```bash
   ./install.sh
   ```

2. **Проверка структуры шаблона:**
   Убедитесь, что скрытые файлы корректно скопировались:
   ```bash
   tree -a ~/pibox/env-template
   ```
   *Ожидаемый результат: Вы должны увидеть `.bashrc`, `.local/bin` и `.pi/agent/` с файлами `.gitkeep`.*

3. **Тест создания нового окружения:**
   Удалите тестовое окружение (если оно есть) и запустите `pibox` с новым именем:
   ```bash
   rm -rf ~/pibox/env/test-env
   mkdir -p /tmp/test-project && cd /tmp/test-project
   
   pibox --env test-env bash
   ```

4. **Проверка внутри контейнера:**
   Внутри запущенного контейнера (в сессии `bash`) выполните:
   ```bash
   ls -la /home/pi
   cat /home/pi/.bashrc | grep mise
   ```
   *Ожидаемый результат: В `/home/pi` должен быть `.bashrc` из шаблона, а `grep` должен найти строку инициализации `mise`.*

5. **Проверка копирования `models.json`:**
   Выйдите из контейнера и проверьте файл в окружении:
   ```bash
   cat ~/pibox/env/test-env/.pi/agent/models.json
   ```
   *Ожидаемый результат: Содержимое файла должно совпадать с шаблоном из `~/pibox/env/models.json`.*
