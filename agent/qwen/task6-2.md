# 📦 PIBOX: Secure Docker Sandbox for Pi Coding Agent

**PIBOX** — это инструмент для безопасного, изолированного и удобного запуска [Pi Coding Agent](https://pi.dev/) в Docker-контейнере. 

AI-агенты с доступом к `bash` и файловой системе представляют риск для хост-машины. PIBOX решает эту проблему, предоставляя агенту песочницу с сохранением состояния (тулчейны, конфиги, история сессий) между запусками, бесшовной интеграцией с файлами проекта и доступом к локальным API.

## 🚀 Quick Start (Быстрый старт)

### 1. Установка и подготовка
Склонируйте репозиторий и запустите установщик. Он создаст рабочую директорию `~/pibox`, скопирует шаблоны окружений и добавит CLI в ваш `PATH`.

```bash
git clone https://github.com/your-repo/pibox.git
cd pibox
./install.sh
```
*Примечание: После установки перезапустите терминал или выполните `source ~/.bashrc` (или `~/.zshrc`), чтобы подхватить новый `PATH`.*

### 2. Сборка Docker-образа
Соберите базовый образ PIBOX. Это займет некоторое время, так как образ включает Node.js, Python, утилиты и сам Pi-агент.

```bash
docker build -t pibox-base:latest .
```

### 3. Запуск агента
Перейдите в директорию вашего проекта и запустите PIBOX:

```bash
cd ~/my-awesome-project
pibox
```
Текущая директория (`~/my-awesome-project`) автоматически примонтируется в `/home/pi/workspace` внутри контейнера, и агент начнет работу.

## 🛠 Использование CLI

Основная команда: `pibox [флаги pibox] [--] [аргументы агента]`

### Основные флаги
| Флаг | Описание |
|---|---|
| `--env <name>` | Использовать указанное окружение (по умолчанию `default`). Если окружения нет, оно создастся из шаблона. |
| `-p <host:cont>` | Пробросить порт из контейнера на хост (например, `-p 8080:8080` для локального dev-сервера). |
| `--git-safe` | Автоматически добавить `/home/pi/workspace` в `git config --global safe.directory`. |

### Примеры
```bash
# Запуск в окружении для PHP-проекта с пробросом порта
pibox --env php8 -p 8000:8000

# Запуск агента с передачей специфичных аргументов самому Pi (используйте --)
pibox --env rust -- --model claude-3-sonnet

# Войти в контейнер в режиме bash (без запуска агента) для отладки
pibox bash
```

## 🧠 Архитектура и концепции

### 1. Окружения (`env/`)
Чтобы агенту не приходилось каждый раз скачивать тяжелые зависимости (Rust, Go, CMake), PIBOX использует систему изолированных окружений.
* При запуске `pibox --env my-env` директория `~/pibox/env/my-env` монтируется как `/home/pi` внутри контейнера.
* Все, что агент установит в `~/.local` (через `mise`), сохранится на хосте и будет доступно при следующем запуске.
* Новые окружения автоматически создаются из `~/pibox/env-template/`.

### 2. Магия `/opt/skel` (Dotfiles)
При запуске Docker-контейнера с bind-mount том `/home/pi` полностью перетирается. Чтобы базовые системные настройки (`.bashrc`, `.profile`, алиасы, инициализация `mise`) не потерялись, при сборке образа эталонный home сохраняется в `/opt/skel`. 
Скрипт `entrypoint.sh` при первом запуске окружения аккуратно "доливает" недостающие файлы из `/opt/skel` в ваше окружение, **не затирая** ваши кастомные конфиги.

### 3. Динамический UID/GID
PIBOX автоматически определяет ваш UID и GID на хост-машине и подстраивает под них внутреннего пользователя `pi` в контейнере. Это гарантирует, что файлы, созданные агентом в вашем проекте, будут принадлежать вам, а не `root` или `nobody`.

## ⚙️ Конфигурация моделей и API

Конфигурация подключений к LLM хранится в файле `models.json`.
1. Глобальный шаблон лежит в `~/pibox/env/models.json`.
2. При первом запуске конкретного окружения он копируется в `~/pibox/env/<имя>/.pi/agent/models.json`.

### Подключение к локальному API
По умолчанию PIBOX настроен на работу с локальным API (например, Ollama, LM Studio или кастомный роутер), запущенным на хост-машине:
```json
{
  "base_url": "http://host.docker.internal:8080/v1"
}
```
*Убедитесь, что ваш локальный API-сервер слушает все интерфейсы (`0.0.0.0`), а не только `localhost`.*

### Безопасность API-ключей
Не храните боевые ключи от облачных провайдеров (OpenAI, Anthropic) в `models.json` в открытом виде. Используйте ссылки на переменные окружения:
```json
"api_key_env": "ANTHROPIC_API_KEY"
```
Само значение переменной можно прописать в `~/pibox/env/<имя>/.bashrc` или передавать при запуске (если вы модифицируете скрипт `bin/pibox`).

## 🛡 Безопасность и Сеть

* **Защита Workspace:** Скрипт запуска строго проверяет (через `realpath`), чтобы вы не запустили `pibox` внутри самой директории `~/pibox`. Это защищает конфиги и шаблоны от случайного удаления агентом.
* **Capabilities:** Контейнер запускается с `--cap-add=SYS_PTRACE` и `--cap-add=NET_RAW`. Это необходимо для корректной работы отладчиков (`gdb`, `strace`) и сетевых утилит (`tcpdump`, `ping`), которые агент может использовать для анализа кода.
* **Ограничения:** По умолчанию контейнер ограничен 2 CPU и 4 GB RAM, чтобы "задумавшийся" агент не повесил хост-машину.
* **Сеть:** Контейнер имеет доступ в интернет для поиска документации и к локальной сети хоста через `host.docker.internal`.

## 🔧 Troubleshooting (Решение проблем)

**Проблема:** `fatal: detected dubious ownership in repository at '/home/pi/workspace'`
**Решение:** Git ругается на смену владельца файлов из-за bind-mount. Запустите PIBOX с флагом `--git-safe`:
```bash
pibox --git-safe
```

**Проблема:** Агент не может подключиться к локальному API на `host.docker.internal:8080`.
**Решение:** 
1. Убедитесь, что API-сервер на хосте запущен и слушает `0.0.0.0:8080`.
2. Если вы используете Linux, убедитесь, что ваш фаервол (ufw/iptables) не блокирует входящие соединения от Docker-моста (`docker0`).

**Проблема:** `Error: Docker image 'pibox-base:latest' not found.`
**Решение:** Вы забыли собрать образ. Выполните `docker build -t pibox-base:latest .` в корне репозитория.

**Проблема:** Тяжелые тулчейны (Rust, Go) не сохраняются между перезапусками.
**Решение:** Убедитесь, что агент устанавливает их в `~/.local` (через `mise`), а не в системные директории (`/usr/local`), так как системные директории сбрасываются при остановке контейнера.
